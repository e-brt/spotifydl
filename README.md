# Spotify Playlist Downloader

A Windows GUI for managing saved Spotify playlist profiles and downloading tracks through [spotDL](https://github.com/spotDL/spotify-downloader).

## Features

- Save multiple playlist profiles, each with a Spotify URL, destination folder, audio format, bitrate and number of download threads.
- Create, duplicate, edit, and delete profiles.
- View spotDL output live, with a progress bar and a track counter; Stop ends every process it started.
- Check existing files before downloading, and download again those that are truncated or below the selected bitrate.
- Use another search result when a YouTube video is age restricted or unavailable.
- A Windows notification when a download ends in the background, and a **Retry failed** button for the tracks that failed.
- **Download all** downloads every profile in turn, without stopping for questions until the end.
- Each run's log is saved in `data\logs\` (**File → Open logs folder**); the latest 100 are kept.
- Keep the folder in sync with the playlist: a `.m3u8` playlist file in the playlist order, and an offer to move to the Recycle Bin the tracks removed from the playlist and, after a format change, the older copies in the previous format.
- Light and dark themes.

See `CHANGELOG.md` for the changes of each version. The current version is shown in the window title and in **Help → About**.

## Download

Prebuilt Windows releases are on the repository's [Releases page](../../releases). Download `SpotifyDownloader-<version>-win64.zip`, check it against the `.sha256` file if you wish, extract it to a user-writable folder (for example under Documents) and run `SpotifyDownloader.exe`.

## Requirements to build from source

- Windows 10 or Windows 11
- Python 3.13 (spotDL supports 3.10 to 3.14)
- Internet access to download the vendor executables

## Prepare the vendor directory

The external executables (Deno, FFmpeg and FFprobe) are not stored in the repository. Download them with:

```powershell
.\fetch_vendor.ps1
```

`vendor.json` pins the exact version and download URL of each one, with the SHA-256 of the archive, of each executable and of its license. The script downloads only what is missing or different, checks every hash, stops without changing anything on a mismatch, and saves the licenses in `vendor\licenses\`. `build.ps1` runs it automatically. To upgrade a component, update its version, URLs and all its hashes in `vendor.json`, and `THIRD_PARTY_NOTICES.md`.

## Create a virtual environment on Windows

Open PowerShell in the project directory:

```powershell
cd D:\Documents\spotifydl
py -3.13 -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

If PowerShell blocks activation scripts, allow them for the current terminal process only:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\venv\Scripts\Activate.ps1
```

In Command Prompt, use `venv\Scripts\activate.bat` instead. `py -3.13` goes through the Python launcher, so the virtual environment gets Python 3.13 even if `python` points to another version.

`requirements.txt` pins the exact version of every package. The worker patches internals of spotDL and some of its dependencies, so upgrade packages on purpose, run a download, then update the pins (see the comment at the top of `requirements.txt`).

## Run from source

```powershell
python src\main.py
```

The code is in `src\`:

| File | Contents |
|---|---|
| `main.py` | entry point: the window, or the worker (`--spotdl-worker`) or the build check (`--self-check`) |
| `main_window.py` | the window: layout, menus, theme, About, closing |
| `profiles.py` | playlist profiles: list, form, create, duplicate, delete, save |
| `downloads.py` | starting and stopping the worker, logs, progress, removal of a track left incomplete by Stop |
| `worker.py` | the spotDL worker process: checking existing files, downloads, fixes applied to spotDL |
| `theme.py`, `widgets.py` | color themes and stylesheet, sun/moon switch |
| `config_manager.py`, `process_control.py`, `resources.py`, `version.py` | configuration, Windows process tree, bundled files, version |

## Run the tests

```powershell
python -m unittest discover -s tests
```

The tests take about 35 seconds and need no network: the GUI tests run the real window with a fake worker (`tests\fake_worker.py`), an in-memory configuration and a temporary folder, so `config.json`, the Spotify cache and your music are never touched. They cover Stop and Close (including the Windows process tree and the removal of a partially written file), the progress bar, the themes, the retry on blocked YouTube videos, the Spotify cache, the quality check of existing files (with files generated by `vendor\ffmpeg.exe`) and the packaged worker self-check. Some tests are Windows only.

## Folder layout and configuration location

The packaged application keeps its folder uncluttered:

```text
SpotifyDownloader\
├── SpotifyDownloader.exe
├── _internal\     application code and libraries
├── data\          config.json, spotify_cache.json and logs\ (your files)
└── docs\          LICENSE, CHANGELOG.md, THIRD_PARTY_NOTICES.md and licenses\
```

The application stores `config.json` in `data\`, next to the executable, or in the project folder when running from source. Files left next to the executable by an earlier build are moved to `data\` on the next start; a file already in `data\` is never overwritten.

Make sure the application folder is writable. If it is installed under a protected location such as `C:\Program Files`, Windows may prevent saving the configuration. Prefer a user-writable folder, such as a folder under Documents.

Use **File → Show configuration location** in the app to display the full path. Back up `config.json` to preserve your saved profiles.

`spotify_cache.json`, in the same folder, keeps Spotify track data between runs so that repeated downloads of the same playlist do not get rate limited by Spotify. It can be deleted at any time; it is rebuilt on the next run.

## Build a Windows executable

From the project directory:

```powershell
.\build.ps1
```

If PowerShell blocks the script, run `powershell -ExecutionPolicy Bypass -File .\build.ps1` instead. The script uses `venv\` or `.venv\` (or the interpreter given with `-Python`) and:

1. reads the version from `src\version.py` and checks that `CHANGELOG.md` has a section for it;
2. downloads or checks the vendor executables with `fetch_vendor.ps1`;
3. checks that the installed packages match `requirements.txt`, then runs the tests (`-SkipTests` skips them);
4. keeps `data\config.json` and `data\spotify_cache.json` from the previous build, which PyInstaller would otherwise delete, and puts them back after the build (a copy is left in the temp folder if the build fails);
5. runs PyInstaller, with the version in the executable's file properties;
6. adds `LICENSE`, `CHANGELOG.md`, `THIRD_PARTY_NOTICES.md` and the third-party license texts (`licenses\`) in `docs\`, next to the executable;
7. checks the output and runs the packaged worker's self-check (`SpotifyDownloader.exe --self-check`), which imports spotDL and applies the worker patches without downloading anything;
8. with `-Package`, writes the release archive `dist\SpotifyDownloader-<version>-win64.zip` and its `.sha256`. The archive never contains the `data\` folder (configuration and Spotify cache).

The executable is created at:

```text
dist\SpotifyDownloader\SpotifyDownloader.exe
```

## Publish a release

1. Set the new version in `src\version.py`, following [Semantic Versioning](https://semver.org/).
2. In `CHANGELOG.md`, move the entries of `[Unreleased]` to a new `## [X.Y.Z] - YYYY-MM-DD` section.
3. Commit, then create and push a matching tag:

   ```powershell
   git tag vX.Y.Z
   git push origin vX.Y.Z
   ```

The `Release` GitHub Actions workflow (`.github/workflows/release.yml`) then builds on Windows with `build.ps1 -Package`, checks that the tag matches `src\version.py`, and publishes a GitHub Release with the zip, its SHA-256 and the changelog section as release notes. The workflow can also be run by hand from the Actions tab: it then only builds the archive and keeps it as a downloadable artifact.

The GUI uses a child process to run spotDL and capture its output. The child process re-launches the packaged executable in worker mode, so do not remove the worker dispatch in `src\main.py`.

## Troubleshooting

- **Missing or damaged FFmpeg or Deno:** run `.\fetch_vendor.ps1` (add `-Force` to download them again).
- **YouTube HTTP 403 or rate limiting:** these are external-source or extractor errors rather than necessarily build errors. Wait before retrying and consider using fewer threads.
- **Profiles missing after a rebuild:** build with `build.ps1`, which keeps `config.json`; a build run by hand with `--clean` deletes the output folder and the files in it.
- **Build fails at the self-check:** a module is missing from the build, or an installed package no longer matches what the worker patches. Reinstall with `python -m pip install -r requirements.txt`.
- **Worker fails to start:** test with `python src\main.py` first and inspect the displayed logs.
